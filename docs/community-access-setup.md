# コミュニティ招待・権限管理の導入手順

## 本番反映前の必須設定

1. Cloudflare のサーバー環境変数に `PLATFORM_OWNER_EMAILS` を追加する。
   - 値はプラットフォームオーナーとして許可するGoogleメールアドレス。
   - 複数必要になった場合のみカンマ区切りにする。
   - `NEXT_PUBLIC_` は付けない。ブラウザへ公開しない。
2. Supabase SQL Editorで `supabase/migrations/20260711_create_community_access.sql` を実行する。
3. アプリをデプロイする。
4. オーナーのGoogleアカウントで一度ログインし、`/admin` が表示されることを確認する。

DBマイグレーションとアプリは同じメンテナンス時間帯に反映する。DBだけ先に反映すると、招待権限を持たない既存ユーザーは即時に個人データへアクセスできなくなる。

## 権限ルール

- プラットフォームオーナーは自分自身のポートフォリオと全体管理画面を利用できる。
- コミュニティ代表者は自分自身のポートフォリオと自コミュニティの会員管理を利用できる。
- 代表者が見られる会員情報は、メール、役割、状態、利用期限、最終利用日時だけ。
- 保有株、資産額、配当、生活費、CSV内容は `user_id` ベースのRLSで本人以外を拒否する。
- 未招待のGoogle認証ユーザーはAuth上に存在しても、アプリと個人データへアクセスできない。

## 運用フロー

1. `/admin` でコミュニティ名、代表者Googleメール、定員を入力する。
2. 代表者用コードを代表者へ送る。発行後14日以内・1回のみ利用できる。
3. 代表者は `/join` でコードを入力し、指定されたGoogleメールで登録する。
4. 代表者は `/community-admin` で会員メールを貼り付けるか、CSV/TXTで一括登録する。
5. 有料PoC開始時にオーナーが「PoCを3か月開始」を実行する。
6. 会員はコミュニティ共通コードと登録済みGoogleメールで参加する。
7. 入金確認後、オーナーが1・3・12か月単位で利用期限を延長する。

## 終了・データ削除

- 契約終了操作でコミュニティと全会員を即時停止する。
- 復帰猶予は30日。
- 30日経過後、次回の認証済みアクセス時に期限切れアカウントの削除処理が実行される。
- 厳密な時刻で自動削除する必要が出た場合は、`purge_expired_community_accounts()` をSupabase Cronから毎日実行する。
- 同じGoogleユーザーが別の有効コミュニティに所属している場合、そのAuthアカウントと個人データは削除しない。

## 最低限の確認項目

- 未登録メール＋正しい共通コード → 登録拒否
- 登録メール＋間違った共通コード → 登録拒否
- 代表者コード＋別メール → 登録拒否
- 停止会員 → ログインしてもポートフォリオ非表示
- 契約終了コミュニティ → 所属者全員が非表示
- 代表者 → 会員一覧は見えるが会員の保有株は取得不可
- オーナー → `/admin` と自分のポートフォリオを利用可能
